## Manual Installation

If you prefer to set up DocuBase from scratch or integrate it into an existing project:

### 1. Create a new Astro project

```bash
npm create astro@latest my-docs
```

### 2. Install required dependencies

```bash
pnpm add @astrojs/mdx @astrojs/tailwind tailwindcss
```

### 3. Configure Astro

Update your `astro.config.mjs`:

```javascript
import { defineConfig } from 'astro/config';
import mdx from '@astrojs/mdx';
import tailwind from '@astrojs/tailwind';

export default defineConfig({
  integrations: [mdx(), tailwind()],
  output: 'static'
});
```

### 4. Set up content collections

Create `src/content.config.ts`:

```typescript
import { defineCollection, z } from 'astro:content';
import { glob } from 'astro/loaders';

const docs = defineCollection({
  loader: glob({ pattern: "**/*.mdx", base: "./src/content/docs" }),
  schema: z.object({
    title: z.string(),
    description: z.string().optional(),
    order: z.number().optional(),
    category: z.string().optional(),
  }),
});

export const collections = { docs };
```

## Troubleshooting

<Collapsible title="Error: Cannot find module or dependency errors">
This usually happens when dependencies aren't installed correctly. Try:

```bash
# Remove existing installations
rm -rf node_modules
rm -f pnpm-lock.yaml package-lock.json yarn.lock bun.lockb

# Reinstall dependencies
pnpm install
```
</Collapsible>

<Collapsible title="Port 4321 is already in use">
Another process is using the default port. You can either:

1. Stop the other process using port 4321
2. Or run on a different port:

```bash
pnpm dev --port 3000
```
</Collapsible>

<Collapsible title="MDX files not rendering correctly">
Ensure you have the MDX integration properly configured:

1. Check that `@astrojs/mdx` is installed
2. Verify it's included in your `astro.config.mjs` integrations array
3. Restart the development server after configuration changes
</Collapsible>

<Collapsible title="Styles not applying correctly">
If Tailwind styles aren't working:

1. Ensure `tailwindcss` and `@astrojs/tailwind` are installed
2. Check that the Tailwind integration is in your config
3. Verify your `tailwind.config.cjs` includes the correct content paths
</Collapsible>

## Environment Configuration

DocuBase works out of the box, but you can customize it with environment variables:

<Table
  headers={["Variable", "Description", "Default"]}
  rows={[
    ["PUBLIC_SITE_URL", "Your site's public URL", "http://localhost:4321"],
    ["PUBLIC_SITE_NAME", "Display name for your docs", "DocuBase"],
    ["PUBLIC_SITE_DESCRIPTION", "Site meta description", "Documentation site"]
  ]}
/>

<Example title="Example .env file" description="Create a .env file in your project root">
```bash
# Site Configuration
PUBLIC_SITE_URL=https://your-docs.vercel.app
PUBLIC_SITE_NAME=My Documentation
PUBLIC_SITE_DESCRIPTION=Documentation for my awesome project
```
</Example>

<Callout type="tip" title="Environment variables">
Variables prefixed with `PUBLIC_` are exposed to the client-side. Keep sensitive values without this prefix.
</Callout>

<Collapsible title="Handling merge conflicts" defaultOpen={false}>
If you've customized DocuBase and encounter merge conflicts:

1. Backup your changes before updating
2. Resolve conflicts in your editor
3. Run `pnpm install` after resolving conflicts
4. Test thoroughly before deploying

```bash
# Create a backup branch before updating
git checkout -b backup/my-customizations
git checkout main
git pull origin main
pnpm install
```
</Collapsible>

</Callout>
